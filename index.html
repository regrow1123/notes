## Closed-Loop Training

자율주행/로봇에서 쓰는 훈련 방식. 시뮬레이션 안에서 AI가 행동하고 그 결과를 다시 학습에 반영하는 순환 구조.

```
Open-Loop (기존):
사람이 운전한 데이터 수집 → 모델 훈련 → 평가
→ AI는 "관찰"만 함, 직접 행동 안 함

데이터: 사람 운전 영상 100만 시간
모델: "이 상황에서 핸들을 왼쪽으로"
문제: AI가 실수했을 때의 상황은 데이터에 없음
(사람은 실수를 안 하니까)
```

```
Closed-Loop (Cosmos):
시뮬레이션에서 AI가 직접 운전
→ 행동 → 결과 → 다시 학습 → 반복

1. AI가 핸들 조작
2. Cosmos가 "그 결과 어떤 장면이 될지" 생성
3. AI가 그 장면을 보고 다음 행동 결정
4. 반복

→ AI의 실수 상황도 학습 가능
→ 실제 도로 안 나가도 됨
```

```
비유:
Open-Loop = 교과서로만 운전 배우기
→ "커브에서 핸들 돌리세요" 읽기
→ 실제로 커브에서 실수하면 대처 못 함

Closed-Loop = 시뮬레이터에서 직접 운전
→ 커브에서 실수 → 사고 남 → 그 경험으로 학습
→ 다음엔 안 틀림
```

**Cosmos의 역할:**

```
기존 시뮬레이션:
3D 엔진 (Unreal, Unity)으로 가상 세계 구축
→ 비싸고, 현실감 부족

Cosmos (World Foundation Model):
실제 영상 데이터로 훈련된 생성 모델
→ "AI가 핸들을 왼쪽으로 돌리면?" → 그에 맞는 영상 생성
→ 물리법칙 반영 (관성, 충돌 등)
→ 몇 달 걸리던 데이터 수집 → 몇 시간
```

```
전체 파이프라인:
Cosmos (세계 모델) → 가상 환경 생성
↓
AI 에이전트가 행동
↓
Cosmos가 결과 시뮬레이션
↓
AI가 결과 보고 학습
↓
반복 (Closed Loop)
```

언리얼엔진이나 Unity에서도 CAD모델에 대해서 변환 지원을 할텐데 어떤 차이가 있는거지?
핵심 차이는 **변환** vs **네이티브 연동**:

```
Unreal/Unity:
CAD 모델 → 변환(import) → 엔진 자체 포맷으로 복사
→ 원본 CAD 수정 → 다시 변환해야 반영
→ 단방향, 1회성

Omniverse (USD):
CAD 모델 → USD로 참조(reference) → 실시간 동기화
→ 원본 CAD 수정 → Omniverse에 자동 반영
→ 양방향, 실시간
```

```
예시: BMW 공장 설계

Unreal 방식:
1. CATIA에서 로봇 팔 설계
2. FBX로 변환 → Unreal에 import
3. Unreal에서 시뮬레이션
4. 설계 변경 → CATIA 수정 → 다시 변환 → 다시 import
→ 매번 변환 반복

Omniverse 방식:
1. CATIA에서 로봇 팔 설계 (CATIA 커넥터 설치)
2. CATIA ↔ Omniverse 실시간 동기화 (USD)
3. 동시에 Blender 디자이너가 외관 작업 (Blender 커넥터)
4. 동시에 엔지니어가 PhysX로 물리 시뮬레이션
5. 누가 수정하든 전부 실시간 반영
→ 변환 없음, 협업 가능
```

```
핵심:
Unreal/Unity = "도구" (자기 안에서 작업)
Omniverse = "플랫폼" (여러 도구를 연결)
```

